# Task 1. BQ

## 1. What is your preferred language when building predictive models and why?

其實我對程式語言的選擇，會根據資料類型以及專案需求甚至是方不方便與team member共同協作而定, 若是進到一個新的環境
即使整個team都在使用其他的程式語言,我也願意配合跟學習,特別是現在有不少成熟的AI 工具,學新的語言完成任務與過往相比不再是件門檻很高的事情
回到此問題,當在建模時,我選擇程式語言取決於當下分析的資料性質。對於主要由數值型與類別型特徵組成的結構化資料，尤其是在使用
統計方法或傳統機器學習模型時，我通常偏好使用 **R** 語言，因為 R 也是我目前最熟悉的程式語言，從剛學習統計時就在使用。R
在統計分析、資料處理以及模型開發方面具有完整的生態系，讓我能夠有效率地進行資料探索並建立預測模型而且這方面的使用跟處理資料的經驗我也足夠。

另一方面，當我處理高維度或非結構化資料，例如影像與文字，或專案涉及較複雜、參數量較大的模型時，我會偏好使用
**Python**。雖然 R 也可以用於深度學習，但 Python 在這個領域擁有更成熟且被廣泛採用的生態系，例如 PyTorch、TensorFlow
等框架，並且在電腦視覺（Computer Vision）與自然語言處理（NLP）方面有非常完整的支援。因此，我認為 Python 更適合用來開發與實驗複雜的深度學習模型。

## 2. Provide an example of when you used SQL to extract data.

在目前半導體產業的 Data Analysis Engineer 工作中，我經常使用 SQL 從 Oracle 資料庫擷取製造與測試資料，用於良率（Yield）與異常分析。

例如，在調查低良率晶圓時，我會使用 SQL 根據產品（Product）、批次（Lot）、晶圓（Wafer）以及時間區間等條件，擷取相關的製造與測試資料。

由於所需要的資訊可能分散在不同的資料表中，因此我會使用 **JOIN**，透過 Lot ID、Wafer ID
等識別欄位，將晶圓資訊、製程量測資料以及測試結果整合在一起。我也會使用篩選（Filtering）與彙總（Aggregation）等方式，先整理出分析所需要的資料集，再進行後續分析或是進行一些系統驗證建立需測試的case。

## 3. Give an example of a situation where you disagreed upon an idea or solution design with a co-worker.  How did you handle the case?

最近，我們其中一個系統的 Data Loader 發生了一個問題。在某些特殊情況觸發下，所有需要的晶圓資料尚未完全載入資料庫之前，演算法就已經被觸發執行，導致演算法使用不完整的資料進行運算，最後產生執行錯誤。

在討論這個問題時，我的主管提出了一個改善流程的方法。不過，我擔心這個方法可能無法完全解決問題的根本原因。當下我沒有直接否定主管的想法，而是先告訴主管，我希望花一些時間進一步分析這個問題。

之後，我重新檢視目前的演算法以及流程中的痛點，並設計了一個替代方案。接著，我與
IT 團隊討論這個方案在技術上的可行性。

確認方案可行之後，我再向主管提出這個方案，並說明我的設計邏輯以及為什麼我認為這個方法能更有效地解決問題。經過討論後，主管認同這個做法，因此我們最後決定採用這個方案繼續進行。

## 4. What are your greatest strengths and weaknesses and how will these affect your performance here?

### 優點

我認為自己最大的優點之一是 **主動改善工作流程**。

在我的分析工作中,難免會遇到資料前處理很複雜亦或是有些定期需要跑資料提供user的任務。遇到這種狀況,我會主動思考是否有機會改善或自動化現有流程，而不是每次遇到相同問題時，都重複以人工方式處理。透過將重複性的工作轉化為可以重複使用的解決方案，當團隊未來再次遇到類似任務或問題時，我可以幫助團隊更有效率地完成工作。

### 缺點

我目前發現自己的一個缺點是，有時候在尚未完全釐清所有需求與限制條件之前，就會太快進入思考解決方案的過程。所以時不時會發生由於一開始對問題的理解不夠完整，導致提出的想法跟所做的事情經過討論後需要進行額外的修改。
為了改善這個問題，我現在養成了一個習慣：在開始想做法並實作之前，會先與需求方完整確認問題定義以及預期結果以減少不必要的重工，同時保有我在解決問題的能力＆提升效率。
